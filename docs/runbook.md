# 操作手冊：收到訊號後怎麼做

網站：https://dennyhty.github.io/grid-trading/ 。系統只給訊號和價位，下單在派網 App 自己做。
系統整體說明見 [system.md](system.md)。

## 1. 收到新訊號

同一個幣、同方向，2H 和 4H 只會出一張（另一個週期的單還沒出場時，新訊號不會出現）。
Telegram 和網站的鈴鐺會收到「BTC/USDT 4H 做多訊號 @ 價格」。只有加密貨幣的實盤策略會推播、會進鈴鐺；網站上的「觀察組」（含美股、商品）不用跟。

1. 打開網站，點那張訊號卡。
2. 往下捲到 **下單計算**：
   - 第一次先填自己的**資金**和**每筆風險 %**（預設 100U、0.25%），之後會記住。
   - 表格會列出每一份的數量（4H、2H 都是四份：TP1/TP2/TP3 各一份、追蹤一份），
     已經照派網的最小下單量和數量級距取整。
   - 寫「已調到最小下單量」時，照最小量下，不要跳過這單；實際止損會比 0.25% 多，下面會寫實際賠多少。
3. 在派網 App 開倉：
   - 方向照訊號（做多 / 做空），數量填「總數量」，市價進場即可（延遲幾分鐘影響很小）。
   - 槓桿只是保證金的多寡，不影響賠多少；賠多少由數量和止損價決定。保證金夠、離強平夠遠就好。
4. 立刻掛**止損**：全部數量，觸發價 = 網站上的 SL。
5. 掛**停利**（只減倉的限價單）：
   - TP1、TP2、TP3 各掛一份（各 1/4），4H、2H 一樣。

## 2. 持倉中

網站和 Telegram 會通知每一個事件，照著改派網的單：

| 通知 | 要做的事 |
|---|---|
| TP1 觸及 | 剩下倉位的止損改到 **BE（保本價）**，網站上有價格 |
| TP2 觸及 | 止損改到 **TP1** |
| 追蹤止損移到 X | 把止損改到 X（網站顯示「目前追蹤止損」） |
| 止損 / 保本 / 追蹤止損出場 | 確認派網的倉位已經平掉，取消剩下的掛單 |
| 逾時平倉 | 240 根 K 線還沒結束（4H 40 天、2H 20 天），市價平掉 |

追蹤止損也可以用派網的「追蹤委託」：觸發價填 TP3，回調比例填網站顯示的 %。

追蹤止損的通知最多晚 15 分鐘；價格跑很快時，以網站的「目前追蹤止損」為準。

## 3. 每週檢討（建議每週日做一次）

1. 網站回測區下方的**實盤紀錄**：筆數、勝率、每筆平均 R，和回測比。
   前 100 筆波動很大，平均 R 落在回測 ±0.25R 內都算正常（約 2 個標準誤）。
2. 對帳：派網的實際成交和網站紀錄是不是一致。差很多通常是漏單、手動提早平倉、或止損沒改到。
   這些會讓實際結果和回測對不起來，比策略本身的影響還大。
3. 有疑問就在專案裡問，例如「這週實盤紀錄比回測差很多，查原因」。

## 4. 系統出狀況

| 狀況 | 怎麼辦 |
|---|---|
| 網站「最後掃描」時間超過 30 分鐘沒更新 | GitHub → Actions → 訊號定時器 → Run workflow 重新啟動（備用排程也會自動檢查、重開） |
| 某些幣的持倉不見了 | 通常是派網限流，下一輪會補回來；持續的話在專案裡說 |
| Telegram 沒收到 | Actions 裡 pages.yml 最後一步的紀錄；token 和 chat id 在 repo 的 Secrets |
| 想暫停所有訊號 | Actions → 訊號定時器 → Disable workflow |
